## 1. Summary

Equip Friday with **self-reflection** (learning from its own past trades)
and **hypothesis validation** (testing logic on history before risking the
live account). This turns a stateless reactor into a system that
accumulates experience.

---

## 2. Problem

- Friday has no memory: it cannot recall how a similar setup played out last
  week, so it repeats losing patterns.
- New strategy logic goes straight to the (testnet) market with no prior
  evidence of whether it would have worked historically.

---

## 3. Goals / Non-Goals

**Goals**
- Persist trade outcomes and retrieve semantically similar past contexts.
- Let the agent simulate a strategy on historical data before live use.

**Non-Goals**
- No change to the multi-agent boundaries from [PRD-003](./PRD-003.md).
- Not a full research backtesting platform — a sandbox sufficient for
  go/no-go gut checks.

---

## 4. Requirements

### 4.1 Trade-log memory

- **R1.** Lightweight vector store. **Decision: embedded local store**
  (`internal/memory`) — in-process, file-backed at
  `~/.friday/memory/trades.jsonl`, cosine similarity over a numeric
  market-feature vector (RSI, price-vs-MA20, momentum, funding, sentiment).
  No external server and no embedding model/API. (Qdrant/Milvus via Go SDK
  was the alternative; rejected to keep friday self-contained and the
  retrieval deterministic + unit-testable. Market-feature vectors are also
  a more faithful notion of "similar market conditions" than text
  embeddings.)
- **R2.** On position close, the Executor calls `log_trade` to store the
  **market context (feature vector), entry reason, bias, and realised
  PnL** as a record (`internal/tool/log_trade.go`).
- **R3.** Before finalising a bias, the Analyst calls `recall_trades` with
  the current indicators; the store returns the top-k most similar past
  trades and their outcomes, which the Analyst weighs into conviction
  (`internal/tool/recall_trades.go`).

### 4.2 Sandbox backtesting

- **R4.** `run_backtest` tool over `internal/backtest`. **Decision:
  structured rule params** (indicator + op + threshold + direction + TP%
  + SL% + leverage) rather than a free-form `strategyLogic string`, so the
  simulation is deterministic and reproducible. `backtest.Run(rule,
  candles)` is the core method the tool wraps.
- **R5.** Returns summary stats — trades, wins, win rate, avg PnL %, total
  return %, max drawdown % (`backtest.Result`).
- **R6.** Backtest runs are isolated — the tool only reads klines; it
  places no orders and mutates no account state.

## 5. Acceptance Criteria

- [x] A closed trade writes a retrievable record (context + reason + PnL).
      — `memory.Store.Log` persists to JSONL and reloads
      (`TestStore_LogPersistsAndReloads`); `log_trade` tool wraps it.
- [x] Given a current setup, the Analyst surfaces ≥1 relevant past trade in
      its report when one exists. — `memory.Store.Similar` ranks by cosine
      similarity and filters by symbol
      (`TestStore_SimilarRanksClosestFirst`); `recall_trades` tool wraps it
      and the Analyst prompt calls it before finalising a bias. (Live
      Analyst behaviour to confirm in a runtime session once memory has
      records.)
- [x] `RunBacktest` returns win-rate stats on a fixed historical fixture
      and places no orders. — `backtest.Run` over a fixture
      (`TestRun_LongInUptrendWins`, leverage scaling, validation); the
      `run_backtest` tool only reads klines (no orders).
- [x] `go build ./...` and `go test ./...` pass.

---

## 6. Out of Scope / Follow-ups

- Online/continual learning or auto-tuning of strategy parameters.
- A standalone backtesting UI or report export.
