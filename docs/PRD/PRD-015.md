---

## 1. Summary

Replace the hardcoded magic-number confidences (momentum 0.60, breakout 0.65,
mean-reversion 0.60, ema-cross 0.55) with **backtest-derived win rates**
computed per-symbol at startup. `backtest.RunStrategy` replays a strategy's logic
over historical candles; `strategy.Calibrate` maps observed win rate → confidence
score. Strategies that empirically work on a symbol get higher voting weight;
those that don't get down-weighted — automatically, per symbol, per session.

---

## 2. Problem

Every strategy currently returns a hardcoded base confidence plus an optional
ADX boost. These numbers were chosen by intuition:

| Strategy        | Base  | Source    |
|-----------------|-------|-----------|
| Momentum        | 0.60  | guessed   |
| Breakout        | 0.65  | guessed   |
| MeanReversion   | 0.60  | guessed   |
| EMACross (new)  | 0.55  | guessed   |

A 0.60 confidence means "this strategy expects a 60% win rate on this setup."
But no one has checked whether momentum on SOLUSDT actually wins 60% of the time,
or 35%, or 80%. The aggregator weights all strategies equally regardless of their
real track record, so a strategy that loses money on a given symbol has the same
vote as one that prints.

---

## 3. Goals / Non-Goals

**Goals**
- `backtest.RunStrategy` replays any `strategy.Strategy` over a candle series and
  reports win rate, avg PnL%, and max drawdown.
- `strategy.Calibrate` runs every strategy against every symbol's recent 4h
  candles at startup, maps win rate → confidence, and injects the results into
  the strategy registry.
- Strategies use calibrated confidences instead of hardcoded values for the rest
  of the session.
- Calibration is best-effort: if it fails (no network, insufficient candles), fall
  back to hardcoded defaults.

**Non-Goals**
- Continuous online re-calibration during a session (startup-only for v1).
- Per-strategy TP/SL optimization — the backtest uses the strategy's own
  invalidation level as the exit.
- Changing the aggregator's consensus rules (≥2 threshold stays; calibrated
  confidences just make the votes more honest).

---

## 4. Requirements

### 4.1 Strategy-aware backtest — `internal/backtest/backtest.go`

- **R1.** `RunStrategy(s strategy.Strategy, symbol string, candles []binance.Kline)
  (Result, error)` — simulates the strategy over the candle series:
  1. Iterate candles oldest-first.
  2. At each candle `i`, call `s.Analyze(symbol, candles[:i+1])`.
  3. If `Signal.Direction != Neutral` and no position is open, enter at
     `candles[i].Close` in that direction.
  4. Exit when price touches `Signal.Invalidation` (the strategy's own stop) or
     the candle series ends (mark to last close).
  5. PnL% = (exit − entry) / entry × leverage (leverage defaults to 1 for
     calibration — we want raw signal quality, not levered returns).
  6. Report trades, wins, winRate, avgPnLPct, totalReturnPct, maxDrawdownPct.
- **R2.** `RunStrategy` reuses the existing `Result` struct and the
  simulateTrade-style exit logic (stop checked before TP on each candle — the
  conservative assumption from `backtest.go:144`).

### 4.2 Calibration pipeline — `internal/strategy/calibrate.go` (new)

- **R3.** `Calibrate(symbols []string, cli *binance.Client, strategies []Strategy)
  map[string]map[string]float64`:
  1. For each symbol, fetch 4h×200 candles from Binance (or use a provided
     `map[string][]binance.Kline` to avoid N sequential API calls).
  2. For each strategy, call `backtest.RunStrategy`.
  3. Map win rate to confidence: `confidence = max(0, (winRate − 0.5) × 2)`.
     - 50% win rate → 0.0 (coin flip, no edge).
     - 75% win rate → 0.5.
     - 100% win rate → 1.0.
     - <50% → 0.0 (negative edge, strategy should not vote).
  4. If a strategy produces <5 trades in the backtest window, mark it as
     "insufficient data" and fall back to the hardcoded default.
- **R4.** Calibration runs **once at startup** in `bootstrap.New()`, after the
  Binance client is available and before the orchestrator is built. Calibrated
  confidences are injected into the `Registry`.

### 4.3 Registry confidence injection — `internal/strategy/registry.go`

- **R5.** `Registry` gains a `calibration map[string]float64` (strategy name →
  calibrated confidence) and a `SetCalibration(m map[string]float64)` method.
- **R6.** `AnalyzeAll` overrides each `Signal.Confidence` with the calibrated
  value when available. ADX boost still applies **additively** on top of the
  calibrated base.

## 5. Acceptance Criteria

- [x] `RunStrategy(Momentum{}, …, uptrendCandles)` reports >0 trades and a win
  rate consistent with the trend (≥0.5). — `TestRunStrategy_MomentumUptrendWins`.
- [x] `RunStrategy(MeanReversion{}, …, fallingCandles)` enters on oversold
  conditions and exits at its invalidation (avg PnL < 0 from the ~1% stops). —
  `TestRunStrategy_MeanReversionExitsAtInvalidation`.
- [x] `Calibrate` returns per-symbol per-strategy confidences; a strategy with
  <`CalibrationMinTrades` (5) trades is omitted (hardcoded fallback). —
  `TestCalibrate_MapsWinRateAndOmitsThin`.
- [x] `Registry.AnalyzeAll` produces signals whose `Confidence` reflects the
  calibrated value + ADX boost (≥0.9 from a 0.9 calibration, not the 0.6
  hardcoded base). — `TestRegistry_AppliesCalibratedConfidence`.
- [x] Calibration failure (no candles) logs a warning and falls back to defaults
  — startup proceeds (`bootstrap.calibrateStrategies` is best-effort).
- [x] `go build ./...`, `go vet ./...`, and `go test ./...` pass.

### Decisions & notes

- **Calibration uses 4h candles** because they provide enough history (200 × 4h =
  ~33 days) for meaningful trade counts without overwhelming the startup time.
  Shorter timeframes (5m) would produce more trades but reflect micro-noise, not
  the strategy's true edge.
- **Leverage = 1 for calibration** — we want to measure signal quality, not
  amplify noise. The Risk Manager applies its own leverage separately.
- **Confidence formula `(winRate − 0.5) × 2`** is deliberately linear and simple.
  It can be replaced with a Kelly-inspired formula later when we have more data.
- **Where the code lives (deviation from R3).** `RunStrategy` is in `backtest`
  as specified (R1, it takes a `strategy.Strategy`), so `backtest` imports
  `strategy`. `Calibrate` therefore had to live in `backtest` too, NOT in
  `strategy` — putting it in `strategy` would create an import cycle
  (`strategy → backtest → strategy`). `strategy` never imports `backtest`; it
  only exposes `SetDefaultCalibration` / `SetCalibration`, which `bootstrap`
  feeds with the map `backtest.Calibrate` returns. Net effect is identical to
  the PRD intent.
- **`Calibrate` is pure (deviation from R3 signature).** It takes a
  `map[string][]binance.Kline` rather than a `*binance.Client`, so it is
  network-free and unit-testable; `bootstrap.calibrateStrategies` does the
  4h×200 fetch per symbol and passes the candles in.
- **Calibration reaches production via a package-global, not a long-lived
  registry.** The trading tools call `strategy.ConsensusFor`, which builds a
  fresh `DefaultRegistry` each round; so the startup calibration is held in a
  process-wide store (`SetDefaultCalibration`) and injected per-symbol on each
  read. The per-`Registry` `calibration` field is the flat `map[string]float64`
  R5 specifies (one symbol's slice), set by `ConsensusFor` before each consensus.
- **Aggregator now abstains on zero-confidence signals.** To honour "a 0-edge
  strategy effectively abstains", `Aggregate` skips any directional signal with
  `Confidence ≤ 0` (so a calibrated-to-0 vote doesn't count toward consensus).
- **ADX boost is additive on top of calibrated base.** This preserves the
  intuition that a strong trend adds conviction regardless of historical win
  rate, while the base rate ensures the strategy starts from an honest floor.
- If calibration shows a strategy has **0% edge on a symbol**, its confidence is
  0.0 and it effectively abstains from voting on that symbol. The aggregator
  ignores zero-confidence signals. This is correct behavior — a strategy that
  backtests at ≤50% win rate should not influence decisions.

---

## 6. Out of Scope / Follow-ups

- Online re-calibration mid-session (currently startup-only).
- Per-strategy optimal TP/SL discovery via backtest parameter sweep.
- Kelly-criterion position sizing from calibrated edge (currently uses fixed 2×ATR).
- Persisting calibration results across sessions so a restart doesn't re-fetch
  33 days of candles.
