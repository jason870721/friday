## 1. Summary

Expand Friday's strategy portfolio from 3 to 5 single-symbol signals: wire the
already-implemented cross-symbol divergence strategy into the live klines data
flow, and add a new EMA crossover strategy. This gives the aggregator enough
votes to form consensus on strong trends — currently momentum and mean-reversion
cancel each other by design, leaving only breakout to decide.

---

## 2. Problem

Friday ships 3 single-symbol strategies (momentum, breakout, mean-reversion).
The aggregator requires ≥2 aligned signals for a consensus. On a strong trend,
momentum fires LONG but mean-reversion — its deliberate counterpart — fires
NEUTRAL (or SHORT if overbought). With only breakout left to confirm, many
tradable trends produce "no consensus."

The cross-symbol divergence strategy (`internal/strategy/divergence.go`) is fully
implemented and unit-tested, but explicitly noted as "not yet wired into the live
per-symbol klines flow." It detects when BTC is flat while another symbol moves
decisively — a genuine edge that is currently sitting idle.

---

## 3. Goals / Non-Goals

**Goals**
- Wire divergence signals into the live klines Summary so the Analyst sees them
  alongside momentum/breakout/mean-reversion.
- Add an EMA crossover strategy as a fourth single-symbol vote (trend-following,
  complements momentum without fully overlapping).
- Aggregator now has ≥4 single-symbol votes + 1 cross-symbol vote → consensus
  forms reliably on trending markets.

**Non-Goals**
- Divergence strategy logic itself is unchanged (already tested).
- No change to the aggregator's ≥2 threshold (the extra votes alone fix the
  "lone signal" problem).

## 4. Requirements

### 4.1 EMA indicator — `internal/binance/indicators.go`

- **R1.** `EMA(values []float64, period int) (float64, bool)` — exponential
  moving average of the last `period` values. `ok` is false when `len(values) <
  period`. Seed from SMA of first `period` values, then apply
  `α = 2/(period+1)` smoothing.

### 4.2 EMA crossover strategy — `internal/strategy/ema_cross.go` (new)

- **R2.** `EMACross` implements `Strategy`.
  - **LONG:** EMA(9) > EMA(21) **and** close > EMA(50) — trend is up and price
    is above the longer-term average.
  - **SHORT:** EMA(9) < EMA(21) **and** close < EMA(50).
  - **Confidence:** `0.55 + adxBoost(ks)` (same ADX boost as momentum/breakout).
  - **Invalidation:** EMA(21) — the signal is void if the fast line crosses back.
- **R3.** Registered in `DefaultRegistry()` alongside momentum/breakout/mean-reversion.

### 4.3 Divergence live wiring — `internal/tool/`

- **R4.** `divergenceHint(symbol string, ks []binance.Kline) string` — a
  package-level function that checks whether the current symbol is diverging from
  BTC (the anchor). It uses a per-round klines cache so the tool layer can
  cross-reference symbols without extra API calls.
  - Cache keyed by symbol, stored in a `sync.Map` (or mutex-protected
    `map[string][]binance.Kline`), cleared at the start of each round by the
    orchestrator (or by the first `binance_mtf_klines` call of the round).
  - When ≥2 symbols are cached (including BTC), run `strategy.DivergenceSignals`
    and return the result for the queried symbol.
  - Anchor defaults to `"BTCUSDT"`; thresholds: `moveThresholdPct=2.0`,
    `flatThresholdPct=0.5` (matching existing test constants).
- **R5.** Both `binance_klines` and `binance_mtf_klines` append the divergence
  hint (when non-empty) to their output, after the strategy consensus line.

### 4.4 Prompt update — `internal/orchestrator/prompts.go`

- **R6.** Analyst prompt §4 (strategy consensus paragraph) updated to mention
  divergence as a cross-symbol signal: "A divergence signal (BTC flat, this
  symbol moving) counts as an independent directional vote — treat it as
  supporting evidence, not a standalone reason to override."

## 5. Acceptance Criteria

- [ ] `EMA(20, closes)` matches hand-calculated values on a known series. —
  `internal/binance/indicators_test.go`.
- [ ] `EMACross` fires LONG on a rising series where EMA(9) > EMA(21) and close
  > EMA(50); fires SHORT on the inverse; stays NEUTRAL when EMAs are tangled. —
  `internal/strategy/strategy_test.go`.
- [ ] `DefaultRegistry()` returns 4 strategies (momentum, breakout,
  mean-reversion, ema_cross).
- [ ] Divergence hint appears in `binance_klines` output when BTC is cached and
  flat while the queried symbol is moving ≥2%.
- [ ] Divergence hint correctly returns empty when BTC itself is trending (no
  divergence setup).
- [ ] Per-round klines cache does not leak between rounds.
- [ ] `go build ./...` and `go test ./...` pass.

### Decisions & notes

- **Why EMA and not MACD?** MACD = EMA(12) − EMA(26) + signal line. It is a
  richer signal but introduces two more parameters and a histogram. EMA(9)/EMA(21)
  crossover is the simplest trend-following building block — it can be upgraded
  to MACD later when calibration data shows whether the extra complexity earns
  its keep.
- **Divergence anchor is hardcoded to BTCUSDT.** If the symbol list doesn't
  include BTC, divergence is a no-op. This is acceptable for the default
  `FRIDAY_SYMBOLS` which always includes BTC. Making the anchor configurable is
  deferred.
- **Cache clearing** — the simplest correct approach: `binance_mtf_klines` (the
  Analyst's primary read) stores each symbol's 5m klines in the cache on every
  fetch. The cache is keyed by symbol and overwritten each round (no explicit
  clear needed — stale data from a prior round is harmlessly overwritten). If a
  symbol's data fetch fails, its cache entry is not updated (stale entry from
  prior round may produce a false divergence hint — acceptable degradation).
