# PRD-011 — Exchange-Truth PnL Reconciliation

| Field        | Value                                                       |
|--------------|-------------------------------------------------------------|
| Status       | Implemented & verified                                      |
| Tranche      | Operational hardening                                       |
| Owner        | Friday team                                                 |
| Source       | Operational — testnet session: a profitable-looking trade with a falling wallet |
| Depends on   | [PRD-004](./PRD-004.md), [PRD-005](./PRD-005.md)            |
| Blocks       | —                                                           |

---

## 1. Summary

Stop trusting the LLM's self-reported PnL. `log_trade` now **reconciles each
closed trade against the Binance income ledger** (`/fapi/v1/income`) — realised
PnL net of commission and funding — and records the exchange's true net. WIN/
LOSS and the circuit breaker both key off that net. A one-off
`cmd/reconcile-memory` tool backfills the same correction onto an existing
`trades.jsonl`.

---

## 2. Problem

The Executor passed a `pnl` number to `log_trade` that the LLM computed from
context. In a live testnet session this was **materially wrong**: two NVDA
shorts were logged as `+0.11` / `+0.94` WINs while the exchange's real realised
P&L was `−4.44` / `−4.46` (net `−4.88` / `−4.90` after fees). The fabricated
wins (a) confused the operator ("I profited but my USDT dropped"), (b) poisoned
the vector memory so `recall_trades` would feed losing setups back as winners,
and (c) fed the circuit breaker the wrong loss signal. Separately, the recorded
figure ignored commission and funding entirely, so even logged losses
understated the true wallet impact.

---

## 3. Goals / Non-Goals

**Goals**
- Record the **exchange's** realised PnL, commission, funding, and net for each
  close — not the agent's estimate.
- Derive WIN/LOSS and feed the circuit breaker from the **net** wallet impact.
- A maintenance tool to repair already-corrupted history.

**Non-Goals**
- No change to how trades are opened/sized; this is accounting only.
- Not a full per-fill ledger — best-effort attribution by symbol + time window
  is sufficient (see notes).

---

## 4. Requirements

### 4.1 Income ledger — `internal/binance`
- **R1.** `Income(symbol, startMs, endMs, limit)` → `[]IncomeEntry`
  (`/fapi/v1/income`, signed).
- **R2.** `SummarizeRealized(rows)` / `RecentRealized(...)` → `RealizedSummary
  {RealizedPnL, Commission, Funding, RealizedRows}` with `Net()`. `RealizedRows
  == 0` signals "nothing matched → caller should fall back".

### 4.2 Reconcile at log time — `internal/tool/log_trade.go`
- **R3.** After a close, query `RecentRealized(symbol, now−90s, now)`. If a
  realised row is found, store the exchange figures with `pnl_source:"exchange"`;
  otherwise keep the agent's value as `pnl_source:"reported"`.
- **R4.** Feed the circuit breaker the **net** (when reconciled), and surface
  the reconciled `realised / fees / funding → NET` in the tool result.

### 4.3 Memory schema — `internal/memory/store.go`
- **R5.** `TradeRecord` gains `commission`, `funding_fee`, `net_pnl`,
  `pnl_source` (all `omitempty`). `DeriveOutcome()` keys WIN/LOSS off `net_pnl`
  when reconciled, else `pnl`; `Store.Log` uses it.

### 4.4 Backfill — `cmd/reconcile-memory`
- **R6.** Read `trades.jsonl`, pull each symbol's income, cluster it into close
  events, greedily match each record to its nearest unused close event (within
  a tolerance), and rewrite PnL/commission/funding/net/outcome — preserving
  `entry_reason` and `features`. Dry-run by default; `-write` backs up to
  `.bak` first.

---

## 5. Acceptance Criteria

- [x] Income rows fold into the correct realised/commission/funding split;
      non-realised windows report `RealizedRows == 0`. —
      `internal/binance/income_test.go`.
- [x] A realised "win" that is a net loss after fees is recorded as LOSS. —
      `internal/memory/outcome_test.go`.
- [x] `cmd/reconcile-memory` matched all 8 historical records to their exchange
      closes; both NVDA WINs flipped to LOSS (net `−4.88` / `−4.90`); original
      backed up to `.bak`.
- [x] `go build ./...` and `go test ./...` pass.

### Decisions & notes
- **Net drives the verdict, not realised price PnL** — the operator cares about
  the wallet, and fees flipped a small realised gain into a net loss.
- **Window attribution (90s live / ±tolerance backfill)** is best-effort: the
  same symbol closed twice within the window could merge, but the WIN/LOSS
  direction stays correct, which is what `recall_trades` and the breaker need.
  Precise per-fill attribution (via `orderId` → `userTrades`) is a follow-up.
- The income query also revealed **fees ≈ 36% of total losses** — over-trading
  / churn is a separate problem (candidate for a future PRD).

---

## 6. Out of Scope / Follow-ups

- Exact per-order attribution by `orderId`/`tradeId` instead of a time window.
- A fee-/churn-budget guard in the Risk Manager (only open when expected move
  clears a higher multiple of round-trip fees).
