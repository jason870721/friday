## 1. Summary

Give the Analyst macro context in one call. A new `binance_mtf_klines` tool
fetches three timeframes concurrently (5m / 1h / 4h), classifies each, and
returns a pre-computed **cross-timeframe alignment** verdict — so a 5m
bullish setup against a 4h downtrend is flagged as a conflict instead of
being traded blind.

---

## 2. Problem

The Analyst reads only 5m candles. Seeing higher-timeframe context requires
several manual `binance_klines` calls across intervals, which it routinely
skips — leaving it with single-timeframe tunnel vision.

---

## 3. Goals / Non-Goals

**Goals**
- One tool returning 5m/1h/4h summaries + a cross-TF alignment verdict.
- Make it the Analyst's primary market-read tool.

**Non-Goals**
- `binance_klines` stays as-is (single-interval quick checks).
- No new indicators beyond reusing MA20/RSI/momentum classification.

---

## 4. Requirements

- **R1.** `ClassifyDirection(ks) string` (BULLISH/BEARISH/NEUTRAL) in
  [`internal/binance/indicators.go`](../../internal/binance/indicators.go):
  BULLISH = price>MA20 & RSI 50–70 & last 3 closes rising; BEARISH the
  mirror; else NEUTRAL. Fixtured tests.
- **R2.** `internal/tool/binance_mtf_klines.go`: fetch 5m×20, 1h×24, 4h×24
  **concurrently** (3 goroutines on the shared `*binance.Client`), build a
  `SemanticSummary` + direction per TF, then a cross-TF verdict
  (ALIGNED / CONFLICT / NO-EDGE, higher-TF bias dominating on conflict).
- **R3.** Register `binance_mtf_klines` for the **Analyst** in
  `orchestrator.New` (the Analyst's tool set) — *not* in `bootstrap.go`'s
  old single-agent wiring.
- **R4.** Update `analystSystemPrompt` in
  [`internal/orchestrator/prompts.go`](../../internal/orchestrator/prompts.go)
  "Method" step so the Analyst calls `binance_mtf_klines` once per symbol
  as its primary read, falling back to `binance_klines` only for extra
  intervals, and weighs the cross-TF verdict into bias/conviction.

---

## 5. Acceptance Criteria

- [x] `ClassifyDirection` returns the expected label on bullish / bearish /
      choppy fixtures (and NEUTRAL when too short). —
      `internal/binance/classify_test.go`.
- [x] `binance_mtf_klines` returns all three timeframes plus an ALIGNED /
      CONFLICT / NO-EDGE verdict; the conflict case defers to the higher
      timeframe. — verdict logic unit-tested in
      `internal/tool/binance_mtf_klines_test.go`; live BTCUSDT rendering to
      confirm in a runtime session.
- [x] The three fetches run concurrently — one `sync.WaitGroup` fan-out over
      the shared `*binance.Client`, not three sequential calls.
- [x] `go build ./...` and `go test ./...` pass.

### Decisions & notes

- **Higher timeframe dominates on conflict:** the verdict scans 5m→1h→4h and,
  when bull and bear both appear, names the highest non-neutral timeframe as
  dominant ("a 5m long against a 4h downtrend is a trap").
- **Graceful degradation:** a single failed timeframe is reported and treated
  as NEUTRAL for the verdict; only an all-timeframes failure returns an error
  (consistent with the per-symbol resilience from PRD-010).
- **ATR still flows:** each TF Summary is `SemanticSummary`, which already
  carries `ATR(14)` (PRD-007), so the Risk Manager keeps its sizing input even
  when the Analyst leads with `binance_mtf_klines`. `binance_klines` stays for
  one-off extra intervals (and its dollar sizing hint).
- **RSI bands exclude extremes** (>70 / <30) so an exhaustion spike is not read
  as trend confirmation.
