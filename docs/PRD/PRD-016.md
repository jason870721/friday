## 1. Summary

Classify the current market state as trending, ranging, or transitional using
ADX(14), then dynamically adjust strategy weights: trend-following strategies
(momentum, breakout, EMA cross) get up-weighted in trends; mean-reversion gets
up-weighted in ranges. Strategies with calibrated confidence ≤ 0.0 are
auto-disabled for the symbol. This prevents the system from fading a strong trend
or chasing a breakout in chop.

---

## 2. Problem

All strategies vote on every symbol every round, regardless of whether the
market regime suits them. Mean-reversion shorts an overbought reading even in a
parabolic uptrend. Momentum goes long into a sideways chop. The aggregator
treats every strategy's vote as equally valid, so a mean-reversion SHORT can
cancel a momentum LONG in a trending market — producing "no consensus" when the
trend is actually clear.

Market regime is the single biggest determinant of which strategy type works:
- **Trending (ADX > 25):** momentum, breakout, EMA cross outperform;
  mean-reversion gets run over.
- **Ranging (ADX < 20):** mean-reversion prints; trend-followers get whipsawed.
- **Transitional (20 ≤ ADX ≤ 25):** no strategy has a reliable edge — prefer
  smaller size or WAIT.

---

## 3. Goals / Non-Goals

**Goals**
- `DetectRegime(ks []binance.Kline) Regime` — pure function, ADX(14)-based.
- `Registry.ConsensusWithRegime(symbol, candles)` — runs strategies, then applies
  regime-based weight multipliers before aggregation.
- Strategies with calibrated confidence ≤ 0.0 are excluded from voting entirely.
- ADX is already computed in `indicators.go` — reuse, don't reimplement.

**Non-Goals**
- No volatility-regime distinction (low-vol grind vs high-vol crash) — ADX alone
  is sufficient for trend-vs-range classification.
- No regime transition prediction (e.g. ADX rising from 18 to 22) — v1 reacts to
  the current reading.
- No per-symbol regime history/persistence.

---

## 4. Requirements

### 4.1 Regime detector — `internal/strategy/regime.go` (new)

- **R1.** `Regime` type: `RegimeTrending`, `RegimeRanging`, `RegimeTransitional`.
- **R2.** `DetectRegime(ks []binance.Kline) Regime`:
  - Compute ADX(14) via `binance.ADX(ks, 14)`.
  - `ADX > 25` → `RegimeTrending`.
  - `ADX < 20` → `RegimeRanging`.
  - Otherwise → `RegimeTransitional`.
  - Insufficient candles for ADX → `RegimeTransitional` (conservative fallback).

### 4.2 Regime-aware weights — `internal/strategy/registry.go`

- **R3.** `Registry` gains per-strategy per-regime weight multipliers:
  ```
  Trending:      momentum ×1.2, breakout ×1.1, ema_cross ×1.2, mean_reversion ×0.3
  Ranging:       momentum ×0.5, breakout ×0.6, ema_cross ×0.5, mean_reversion ×1.3
  Transitional:  all ×1.0 (no adjustment)
  ```
  Multipliers are constants in `registry.go`.
- **R4.** `ConsensusWithRegime(symbol string, candles []binance.Kline) Consensus`
  — calls `AnalyzeAll`, applies regime weight multipliers to each signal's
  `Confidence`, then calls `Aggregate` as before.
- **R5.** `Consensus()` (existing, no-regime) remains available for callers that
  don't have ADX data (e.g. the Analyst's `binance_klines` with <29 candles).
  `binance_mtf_klines` (which always has 4h×24 candles) uses `ConsensusWithRegime`.

### 4.3 Auto-disable zero-confidence strategies

- **R6.** After calibration (PRD-015), any strategy whose calibrated confidence
  is 0.0 for a given symbol is excluded from `AnalyzeAll` for that symbol. This
  is a natural extension of the calibration pipeline — a strategy with no edge
  should not vote.

### 4.4 Wiring — `internal/tool/binance_mtf_klines.go`

- **R7.** The 4h timeframe has enough candles for ADX(14) (needs 29; 4h×24=24
  candles is insufficient — use 4h limit of at least 30 for regime detection, or
  compute ADX from the 1h timeframe which has 24 candles... also insufficient).
  **Resolution:** increase `binance_mtf_klines` 4h limit from 24 to 48 (still
  concurrent, still one turn — well within rate limits). 48×4h = 8 days, more
  than enough for ADX(29).
- **R8.** The cross-TF verdict section in `binance_mtf_klines` output appends the
  regime classification from the 4h candles: `Regime: TRENDING (ADX 34.2) →
  favoring momentum/breakout/ema_cross.`

## 5. Acceptance Criteria

- [ ] `DetectRegime(strongTrendCandles)` returns `RegimeTrending`. —
  `internal/strategy/regime_test.go` (or `strategy_test.go`).
- [ ] `DetectRegime(choppyCandles)` with ADX < 20 returns `RegimeRanging`.
- [ ] `DetectRegime(insufficientCandles)` returns `RegimeTransitional`.
- [ ] `ConsensusWithRegime` on a trending series up-weights momentum ×1.2 and
  down-weights mean-reversion ×0.3.
- [ ] A strategy with calibrated confidence 0.0 is absent from the signal list.
- [ ] `binance_mtf_klines` output includes regime classification when ADX is
  computable.
- [ ] `go build ./...` and `go test ./...` pass.

### Decisions & notes

- **Weight multipliers are constants, not calibrated.** They encode domain
  knowledge ("mean-reversion loses in trends") rather than fitted parameters. A
  future iteration could fit these from historical per-regime strategy
  performance (PRD-014's tracking data).
- **Regime is detected from 4h candles**, the highest timeframe in the MTF read.
  This is deliberate: regime is a structural property that changes slowly; 5m
  ADX would oscillate between trending/ranging every few hours and cause strategy
  weights to thrash.
- **Transitional regime applies no weight adjustment.** When ADX is 20-25, the
  market hasn't committed to a direction — the safest move is to let strategies
  vote at their calibrated base weights without amplification. The aggregator's
  ≥2 consensus rule naturally produces NEUTRAL when signals disagree.
- **4h limit increase (24→48)** adds ~2KB to the API response per symbol. At 7
  symbols this is negligible. The alternative — computing ADX from 1h candles
  and accepting a shorter lookback — would make regime detection noisier.

---

## 6. Out of Scope / Follow-ups

- Volatility sub-classification (high-vol trending vs low-vol grind).
- Regime transition early-warning (ADX slope).
- Per-regime position sizing adjustments (e.g. half size in transitional).
- Fitting weight multipliers from historical per-regime strategy P&L.
