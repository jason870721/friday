## 1. Summary

Run the strategy engine on all three timeframes already fetched by
`binance_mtf_klines` (5m/1h/4h), then aggregate into a weighted cross-timeframe
vote where higher timeframes dominate on conflict. The Analyst currently reads
each timeframe's `ClassifyDirection` (BULLISH/BEARISH/NEUTRAL) as raw text; this
PRD replaces that qualitative read with a quantitative multi-timeframe strategy
consensus — the same strategies, running on actual 1h and 4h candles, not just
a coarse direction heuristic.

---

## 2. Problem

`binance_mtf_klines` fetches 5m×20, 1h×24, and 4h×48 candles concurrently, but
only the 5m candles are fed to the strategy engine (via `SemanticSummary`'
internal `strategy.ConsensusFor` call). The 1h and 4h data is reduced to a
single-word direction (`ClassifyDirection`) and a text summary. This means:

- A 5m momentum LONG that contradicts a 4h downtrend still votes LONG at full
  confidence.
- The Analyst sees "4h BEARISH" as text and is told to "let the higher timeframe
  dominate," but this is a prompt instruction the LLM can ignore or forget.
- The strategy engine's calibrated confidences (PRD-015) and regime-aware weights
  (PRD-016) only apply to 5m — the richer higher-timeframe data gets none of
  that rigor.

---

## 3. Goals / Non-Goals

**Goals**
- Run the full strategy registry on 1h and 4h candles in `binance_mtf_klines`.
- Aggregate the three per-timeframe consensuses into a single MTF vote, where
  higher timeframes carry more weight (5m ×1.0, 1h ×1.5, 4h ×2.0).
- Report the MTF consensus as a structured line in the tool output, replacing or
  supplementing the current `ClassifyDirection`-based cross-TF verdict.

**Non-Goals**
- No change to how `binance_mtf_klines` fetches data (intervals, limits).
- No change to the Analyst prompt's cross-TF logic (the MTF consensus is
  additional evidence; the prompt's "higher TF dominates" rule remains as a
  backstop).
- No per-timeframe calibration (the same calibrated confidences from PRD-015
  apply across timeframes — a strategy that wins on 5m is assumed to generalize;
  separate per-TF calibration is a follow-up).

---

## 4. Requirements

### 4.1 MTF aggregation — `internal/strategy/aggregator.go`

- **R1.** `AggregateMTF(consensusByTF map[string]Consensus) Consensus`:
  - Input: `{"5m": Consensus, "1h": Consensus, "4h": Consensus}` (or fewer, if a
    TF failed to fetch).
  - Weighted direction vote: sum `directionWeight * tfWeight` across timeframes,
    where `directionWeight = +Confidence` for LONG, `−Confidence` for SHORT, `0`
    for NEUTRAL.
  - TF weights: `5m=1.0, 1h=1.5, 4h=2.0`.
  - Final direction: LONG if net > +0.1, SHORT if net < −0.1, NEUTRAL otherwise
    (a hysteresis band to prevent flipping on noise).
  - Final confidence: `abs(net) / sum(tfWeights)` clamped to [0,1].
  - Summary describes which TFs agreed/disagreed.
- **R2.** The existing `Aggregate` (single-TF) is unchanged — `AggregateMTF`
  calls it internally per TF, then combines the results.

### 4.2 Wiring — `internal/tool/binance_mtf_klines.go`

- **R3.** After fetching all three TFs, run `strategy.DefaultRegistry().Consensus()`
  (or `ConsensusWithRegime` from PRD-016) on each TF's klines.
- **R4.** Call `strategy.AggregateMTF()` on the three per-TF consensuses.
- **R5.** Append an `MTF Strategy:` line to the output, replacing or
  supplementing the current `Cross-TF:` line:
  ```
  MTF Strategy: LONG (5m:LONG 0.62 + 1h:NEUTRAL + 4h:LONG 0.71) → weighted LONG 0.48
  ```
  The old `ClassifyDirection`-based cross-TF verdict is retained as a separate
  line for the Analyst's qualitative context.

### 4.3 Analyst prompt — `internal/orchestrator/prompts.go`

- **R6.** The Analyst prompt's cross-TF section (§3) updated: "The `MTF Strategy`
  line gives a quantitative multi-timeframe strategy vote — treat it as the
  primary directional signal. The `Cross-TF` line is qualitative context. When
  they disagree, prefer the MTF Strategy (it runs the same calibrated strategies
  on actual higher-TF candles)."

### Decisions & notes

- **TF weights (1.0 / 1.5 / 2.0) are chosen so 4h outweighs 5m but doesn't
  completely silence it.** A 4h SHORT at 0.60 confidence contributes −1.2 to the
  net; a 5m LONG at 0.70 contributes +0.70. Net = −0.50 → SHORT. The 4h wins
  but the 5m still influences the final confidence (0.50 / 4.5 ≈ 0.11 — low,
  reflecting the disagreement).
- **Hysteresis band (±0.1)** prevents the MTF consensus from flipping LONG/SHORT
  on tiny net-score changes between rounds. Inside the band, direction stays
  NEUTRAL.
- **`ClassifyDirection` is retained** because it captures a simpler, coarser
  signal (price vs MA20 + RSI zone + last 3 closes) that the Analyst can use to
  sanity-check the strategy output. The two can disagree — e.g. strategies might
  say LONG but `ClassifyDirection` says NEUTRAL because RSI is 72 (overbought
  and excluded by the bands). The Analyst sees both and can reason about the gap.
- **Per-TF calibration is deferred** because it requires per-TF trade attribution
  in the memory store (PRD-014 only adds a `strategy` field, not a `timeframe`
  field). Once that exists, calibration can run separately for 5m/1h/4h and
  produce TF-specific confidences.
- **Each TF uses `ConsensusForWithRegime` (PRD-016), not plain `Consensus`.** R3
  sanctions either; the regime-aware variant gives every TF the full calibration
  + regime rigor. In practice only the 4h frame has ≥29 candles for ADX, so 5m/1h
  resolve to `RegimeTransitional` (no weight change — calibrated only) while 4h
  gets real regime weighting. This naturally keeps regime a 4h-structural property
  (consistent with PRD-016) without extra plumbing.
- **The MTF line supersedes PRD-016's standalone "4h regime-weighted" consensus
  line**, which was removed — the `MTF Strategy:` line already shows the 4h
  contribution (regime-weighted) alongside 5m/1h. The PRD-016 `Regime:` line
  (classification + ADX) is retained.

---

## 6. Out of Scope / Follow-ups

- Per-timeframe strategy calibration (needs `timeframe` field on `TradeRecord`).
- Adaptive TF weights that shift based on which TF's strategies are performing
  best.
- A "TF alignment score" surfaced to the Risk Manager for position sizing (e.g.
  full size when all 3 TFs agree, half size when only 5m fires).
