---

## 1. Summary

Surface each strategy's `Invalidation` level — already computed internally for
every signal — in the klines Summary, and instruct the Risk Manager to prefer it
over the generic 2×ATR stop when it offers tighter protection. This gives each
strategy's exit logic equal status with its entry logic: momentum exits when
price breaks MA20, breakout exits when price falls back into the range,
mean-reversion exits when the stretch continues past invalidation.

---

## 2. Problem

Every `Signal` already carries an `Invalidation` field representing the price
level at which the strategy's thesis is void:

| Strategy        | Invalidation            | Meaning                                  |
|-----------------|-------------------------|------------------------------------------|
| Momentum        | MA20                    | trend broken — exit                      |
| Breakout        | priorHigh (long) / priorLow (short) | back inside range — fakeout   |
| MeanReversion   | entry × 0.99 / 1.01     | stretch continuing — reversal failed     |
| EMACross        | EMA(21)                 | fast line crossed back — trend over      |

But this field is **never surfaced to the Risk Manager**. The klines Summary
line reports the strategy consensus direction and confidence, but not the
invalidation level that comes with it. The Risk Manager uses a uniform 2×ATR
stop for every trade, regardless of which strategy triggered it.

A uniform stop means:
- Mean-reversion trades (which expect a quick snap-back) use the same stop
  distance as momentum trades (which expect a sustained move). The risk budget
  is misallocated.
- The strategy's own "I am wrong" level — the one that was validated in backtest
  — is ignored in favor of a generic volatility stop.

---

## 3. Goals / Non-Goals

**Goals**
- `binance_klines` and `binance_mtf_klines` output include each strategy's
  invalidation level alongside its direction and confidence.
- Risk Manager prompt instructs: prefer the strategy's invalidation level as the
  stop-loss when it is **tighter** (closer to entry) than the 2×ATR stop. When
  invalidation is looser, use 2×ATR but treat invalidation as a hard mental stop.
- The `Signal.Invalidation` field already exists and is populated — this PRD only
  surfaces it.

**Non-Goals**
- No change to the StopMonitor or `binance_stop_monitor` tool (it continues to
  use whatever stop the Executor passes; the Risk Manager's choice of stop level
  is what changes).
- No change to take-profit logic (still the Risk Manager's 7-check tiers).
- No per-strategy TP levels.

---

## 4. Requirements

### 4.1 Klines output — `internal/tool/binance_klines.go`

- **R1.** The `Strategy signals:` line in `binance_klines` output is extended
  to include each contributing strategy's invalidation level:
  ```
  Strategy signals: LONG (confidence 68%) — momentum(62% inval=95234.12) + breakout(74% inval=96100.50).
  ```
  Currently it says `momentum(62%) + breakout(74%)` without invalidation.
- **R2.** `strategy.FormatSummary` updated to accept and render per-signal
  invalidation levels.

### 4.2 MTF klines output — `internal/tool/binance_mtf_klines.go`

- **R3.** The per-timeframe `[5m] Summary → BULLISH` line is unchanged (it uses
  `ClassifyDirection`, not strategy signals). The new `MTF Strategy:` line
  (PRD-017) includes invalidation as above.

### 4.3 Risk Manager prompt — `internal/orchestrator/prompts.go`

- **R4.** The sizing section (§ "Sizing") updated with an invalidation-priority
  rule:
  > **Stop-loss priority.** The strategy signals in the Analyst's klines Summary
  > include an invalidation level (the price at which the strategy's thesis is
  > void). When setting `stop_loss` for an OPEN:
  > - If the strategy's invalidation is **closer to entry** than 2×ATR → use
  >   invalidation as the stop (tighter protection).
  > - If invalidation is **farther** than 2×ATR → use 2×ATR as the stop, but
  >   note the invalidation in your `reason` as the hard mental stop.
  > - If multiple strategies contributed to the consensus, use the **closest**
  >   invalidation among the agreeing strategies (the most conservative one).
  > - If no invalidation is available (e.g. the Analyst used NEUTRAL and you are
  >   trading on macro context), fall back to 2×ATR.

### 4.4 Signal struct — no change needed

The `Signal.Invalidation` field (`internal/strategy/strategy.go:37`) is already
`float64` with `0 = n/a` semantics. All four strategies already populate it.
No struct change is required.

## 5. Acceptance Criteria

- [ ] `binance_klines` Strategy signals line includes invalidation levels for
  each strategy that fired. — verify by inspecting tool output.
- [ ] `FormatSummary` with a LONG consensus from momentum + breakout renders both
  strategies' invalidation levels.
- [ ] Risk Manager prompt includes the stop-loss priority rule referencing
  strategy invalidation.
- [ ] When a strategy returns `Invalidation = 0` (n/a), it is omitted from the
  output (not printed as `inval=0.00`).
- [ ] `go build ./...` and `go test ./...` pass.

### Decisions & notes

- **"Closest invalidation" is the conservative choice.** When two strategies
  agree on LONG, using the tighter invalidation means we exit sooner if either
  strategy's thesis breaks. This is appropriate for a system that prioritizes
  capital preservation.
- **Why not make invalidation the ONLY stop?** Because the strategy's
  invalidation is a structural level (MA20, range boundary) — it doesn't account
  for account-level risk. The 2×ATR stop is a risk-budget stop: "I am willing to
  lose X% of my balance on this trade." Both are useful. The rule "use whichever
  is tighter" means the position is protected by both structural and risk-budget
  logic.
- **Take-profit is deliberately unchanged.** Strategy-specific TP levels
  (momentum: trail MA20; mean-reversion: exit at MA20) are a larger design
  change that affects the Risk Manager's 7-check framework. This PRD focuses on
  the stop side because (a) the field already exists, (b) stops prevent
  catastrophic loss, and (c) TP optimization can build on the same invalidation
  infrastructure later.

---

## 6. Out of Scope / Follow-ups

- Strategy-specific take-profit levels (e.g. mean-reversion exits at MA20
  instead of a fixed % gain).
- Trailing stop based on strategy invalidation (e.g. move stop to MA20 as it
  rises).
- Invalidation levels for divergence signals (divergence currently sets
  `Invalidation = 0` — the anchor breaking its flat range could serve as one).
