---

## 1. Summary

Decompose Friday's single monolithic agent into three collaborating roles
to solve context overload and to enforce a clean separation between
analysis, risk control, and execution. Each role is implemented with Go
**structs and interfaces**, with handoffs passed as typed values
(optionally over **goroutines/channels** if rounds run concurrently). Each
agent has a narrow mandate and a narrow tool set.

---

## 2. Problem

- One agent juggles market reading, sizing, risk vetting, and order
  placement in a single context window. As phases 1–2 add semantic data,
  sentiment, and guardrail feedback, the context grows noisy and the model
  loses focus.
- Mixing "should we trade?" with "how big and how to execute?" in one
  reasoning pass makes failures hard to attribute and hard to constrain.

---

## 3. Goals / Non-Goals

**Goals**
- Three single-responsibility agents with explicit, typed handoffs.
- Risk authority concentrated in one agent that can veto.
- Smaller, cleaner context per agent.

**Non-Goals**
- No new data sources or indicators beyond phases 1–2.
- No long-term memory / backtesting ([PRD-004](./PRD-004.md)).

---

## 4. Requirements

Break the monolith into three entities:

- **R1. Analyst Agent.** Consumes the semantic data + sentiment tools from
  PRD-001/002 and produces a structured **market analysis report**
  (bullish / bearish context, key levels, conviction). No trade authority.
- **R2. Risk Manager Agent.** Reads the Analyst report, computes position
  size, sets stop-loss / take-profit, applies the seven risk checks and the
  hard guardrail from PRD-002, and may **veto** a proposal outright. Emits
  strict numeric parameters only.
- **R3. Executor Agent.** Receives validated numeric parameters from the
  Risk Manager and performs the precise Binance calls
  (`binance_leverage`, `binance_order`). It does not re-decide direction or
  size.
- **R4.** Define the handoff contracts as Go types (report struct → risk
  decision struct → execution-params struct) so each boundary is
  machine-checkable; communicate them as plain return values or over
  channels if the three roles run as concurrent goroutines.
- **R5.** Tool catalogs are scoped per agent: Analyst gets read/sentiment
  tools, Risk Manager gets account/position reads, Executor gets the
  trading tools.

### Implementation notes

- **Programmatic orchestration** (not SDK-native subagents): three
  `agent.Agent` instances driven by `Orchestrator.Run`, whose signature
  matches `agent.Agent.Run` so the TUI is unchanged but for role-tagged
  events (`[Analyst]` / `[Risk]` / `[Executor]` / `[Pipeline]` prefixes via
  `AgentEventMsg.Source`).
- **Typed handoffs via `submit_*` tools.** Each role ends by calling a
  schema-validated capture tool (`submit_analysis` / `submit_risk_decisions`
  / `submit_execution`); the orchestrator reads the struct from a `capture`
  slot. This is how LLM output becomes a machine-checkable Go value.
- **The orchestrator owns the loop and 15s cadence**, replacing the old
  per-agent `schedule_wakeup`. "Never stop the loop" is now a Go `for`
  loop bounded by context cancellation (Ctrl+C), not a prompt rule. The
  monolithic `bootstrap/prompt.go` is removed; its content is split across
  the three role prompts in `internal/orchestrator/prompts.go`.
- Goroutines/channels were not needed — the per-round pipeline is
  inherently sequential (Analyst → Risk → Executor).

## 5. Acceptance Criteria

- [x] A single round produces a traceable chain: Analyst report → Risk
      decision (size/SL/TP or veto) → Executor action (or no-op on veto). —
      `Orchestrator.runRound` in `internal/orchestrator/orchestrator.go`;
      typed handoffs `AnalystReport → RiskDecisions → ExecutionResult` in
      `types.go`, captured via schema-validated `submit_*` tools
      (`capture.go`). Covered by `TestRunRound_FullPipeline`.
- [x] A high-risk proposal is vetoed by the Risk Manager and no order is
      placed. — `RiskDecision.Action == "VETO"`; the orchestrator skips the
      Executor entirely when nothing is actionable
      (`TestRunRound_SkipsExecutorWhenNothingActionable`).
- [x] The Executor never originates a trade not authorized by the Risk
      Manager. — Executor receives only the `RiskDecisions` JSON and its
      prompt forbids re-deciding; tool sets are disjoint (Analyst/Risk have
      no trading tools). Runtime transcript check pending live verification.
- [x] `go build ./...` and `go test ./...` pass.
