# PRD-010 — Configurable, Venue-Validated Symbol Universe

---

## 1. Summary

Replace the hardcoded `BTCUSDT/ETHUSDT/SOLUSDT` trio with a **configurable
symbol list** (`FRIDAY_SYMBOLS`) that is **validated against the venue's
`exchangeInfo` at startup**: only symbols the endpoint lists as `TRADING`
survive, each carrying its real `LOT_SIZE` step. The validated set is injected
into the three role prompts and the `submit_*` schemas, so adding or removing a
market is a config change, not a code change. Stock-linked (TradFi) perps
additionally require a one-time account agreement, which bootstrap signs
automatically.

---

## 2. Problem

The covered symbols were string literals scattered across six places (three
role system prompts, two round-prompt builders, and the `submit_*` schemas'
`minItems: 3`). Adding markets meant editing all six and re-deriving per-asset
step sizes by hand. Worse, stock perps on Binance USDⓈ-M Futures (contractType
`TRADIFI_PERPETUAL`) (a) may not exist on a given endpoint (testnet vs mainnet
differ), which would make the Analyst error on an invalid symbol every 15s
round, and (b) reject orders with code `-4411` until an account-level
agreement is signed.

---

## 3. Goals / Non-Goals

**Goals**
- One configurable, deduped, normalised symbol list (`FRIDAY_SYMBOLS`).
- Startup `exchangeInfo` preflight that drops non-`TRADING` symbols (logged),
  so the per-round pipeline never iterates an unavailable market.
- Real per-symbol `LOT_SIZE` step fed to the Risk Manager (replacing stale
  hardcoded steps).
- Auto-sign the TradFi-Perps agreement so stock-perp orders are accepted.

**Non-Goals**
- No change to strategy logic, sizing math, or the 15% guardrail.
- Not asserting stock perps are a good trade — just making them tradable and
  safe to enumerate.

---

## 4. Requirements

### 4.1 Symbol config + validation — `internal/bootstrap`
- **R1.** `FRIDAY_SYMBOLS` (comma-separated; default = 3 crypto + 4 stock
  perps) parsed/normalised/deduped (`parseSymbolList`).
- **R2.** `resolveSymbols` calls `exchangeInfo` (public/unsigned) once; keeps
  `Status == "TRADING"`, attaches `StepSize`, logs+drops the rest, and prints
  the final `friday: trading N symbol(s): …` line. Degrades to validated core
  pairs if the preflight is unreachable; errors if zero survive.

### 4.2 Venue data — `internal/binance`
- **R3.** `ExchangeInfo()` → `[]SymbolInfo{Symbol, Status, ContractType,
  StepSize}` + `IsTradFiPerp()`.
- **R4.** `SignTradFiPerpsAgreement()` → `POST /fapi/v1/stock/contract`
  (signed, idempotent). `client.do` must treat `code 200` as success (real
  errors are negative).

### 4.3 Wiring — `internal/orchestrator`
- **R5.** `orchestrator.New` takes `[]MarketSymbol{Name, StepSize}`; the three
  system prompts are token-templated (`{{SYMBOLS}}`/`{{COUNT}}`/`{{STEPS}}`)
  and the round-prompt builders use the live list. `submit_analysis` /
  `submit_risk_decisions` schemas pin `minItems` to the symbol count.
- **R6.** Prompts harden against a mid-round data error for one symbol:
  Analyst marks it NEUTRAL/unavailable and moves on; Executor reports and skips
  — never retry-loops or aborts the round.

### 4.4 Auto-sign
- **R7.** `resolveSymbols` signs the TradFi-Perps agreement when any resolved
  symbol `IsTradFiPerp()` and credentials are present. A sign failure is a
  logged warning, not a crash or a symbol drop (market data works without it).

## 5. Acceptance Criteria

- [x] `exchangeInfo` parses status/contractType/step; non-`TRADING` symbols are
      dropped with a log line. — `internal/binance/exchangeinfo_test.go`,
      `internal/bootstrap/symbols_test.go`.
- [x] Prompts/schemas render from the live list; `%`-literals survive; schema
      `minItems` tracks the count. — `internal/orchestrator/prompts_test.go`.
- [x] TradFi-Perps agreement signs via `POST /fapi/v1/stock/contract`; `code
      200` is treated as success. — `internal/binance/tradfi_test.go`.
- [x] Live testnet: all 7 configured symbols resolve `TRADING`; agreement
      signed; stock-perp orders no longer rejected with `-4411`.
- [x] `go build ./...` and `go test ./...` pass.

### Decisions & notes
- Default list ships the 4 stock perps even though availability varies — the
  preflight resolves away any the endpoint doesn't list, so the config is
  forward-compatible (they activate automatically once listed).
- `MSFTUSDT` was swapped for `AMZNUSDT` after testnet was found not to list MSFT.
- Step sizes are sourced live from `LOT_SIZE`; the old hardcoded
  `BTC 0.001 / ETH 0.01 / SOL 0.1` were also simply wrong vs testnet.

---

## 6. Out of Scope / Follow-ups

- A total-exposure cap: with `max_positions` now = N (7), N full-size positions
  can exceed the 60% total-margin budget sooner — tighten in the Risk Manager.
- Per-symbol leverage/min-notional rules from `exchangeInfo` (only `LOT_SIZE`
  is consumed today).
