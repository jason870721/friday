## 1. Summary

Friday currently feeds raw OHLCV arrays to the LLM and lets it act on them
directly. The decision-making is short-sighted and easily disrupted by
market noise. This PRD makes the agent **understand** market data
contextually and **reason before acting**.

Two changes, both low-risk and high-leverage:

1. Convert numeric market data into natural-language context enriched with
   technical indicators.
2. Force a structured reasoning step (ReAct) before any trade command is
   emitted.

---

## 2. Problem

- The model receives `binance_klines` candles as bare numbers and has to
  re-derive trend/momentum every round, inconsistently.
- There is no enforced separation between *reasoning* and *acting*, so the
  model can fire a `binance_order` call without a defensible thesis.
- Noise (single-candle wicks) is over-weighted because the model lacks
  smoothed indicators to anchor on.

---

## 3. Goals / Non-Goals

**Goals**
- Emit a semantic, indicator-annotated market summary the LLM can read at a
  glance.
- Guarantee every action is preceded by an explicit `<Thought>` analysis.

**Non-Goals**
- No new external data sources (that is [PRD-002](./PRD-002.md)).
- No change to the multi-symbol loop or risk caps.
- No new order types — MARKET only, as today.

---

## 4. Requirements

### 4.1 Data preprocessing → natural language

- **R1.** Add indicator helpers over the OHLCV series returned by
  `binance_klines` (`internal/tool/binance_klines.go` /
  `internal/binance/market.go`): at minimum **MA20** and **RSI(14)**.
- **R2.** Render the result as a natural-language string, e.g.
  *"Price 64,210 has broken above MA20 (63,800); RSI 72 (overbought);
  24h volume +18%."*
- **R3.** The semantic summary is surfaced to the agent per symbol each
  round, alongside (not replacing) the raw tool output.

### 4.2 ReAct framework

- **R4.** Update the system prompt in
  [`internal/bootstrap/prompt.go`](../../internal/bootstrap/prompt.go) to
  require a `<Thought>` block before any execution command.
- **R5.** The `<Thought>` block must state the observed trend and why the
  proposed action (LONG / SHORT / CLOSE / WAIT) aligns with the strategy
  and the seven risk checks.
- **R6.** If no `<Thought>` precedes an action, that is a prompt-compliance
  defect to be corrected (no silent action).

## 5. Acceptance Criteria

- [x] Each round, every symbol shows a one-line semantic summary including
      MA20 and RSI. — `binance.SemanticSummary`, appended to every
      `binance_klines` result as a `Summary:` line.
- [x] Indicator math is unit-tested against a fixed candle fixture. —
      `internal/binance/indicators_test.go` (SMA, Wilder RSI edges/range,
      summary rendering).
- [x] No `binance_order` / `binance_leverage` call appears in a transcript
      without a preceding `<Thought>` block. — enforced by Iron Rule #5 and
      the "ReAct" section in `internal/bootstrap/prompt.go`; verify in a
      live testnet transcript.
- [x] `go build ./...` and `go test ./...` pass.
