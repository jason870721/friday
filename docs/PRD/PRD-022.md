## 1. Summary

Two changes to the strategy signal engine, both driven by empirical loss analysis of
12 live trades (1W/11L, WR=8.3%):

1. **RSI zone entry filter** — a global gate in `AggregateMTF` that blocks
   directional signals when 5m RSI is at an extreme (≥75 overbought or ≤25 deep
   oversold), preventing the engine from voting LONG into a peak or SHORT into a trough.

2. **MTF responsiveness tuning** — lower the hysteresis band from ±0.1 to ±0.05 and
   add a 5m+1h consensus override so that aligned lower-timeframe signals can fire
   even when the 4h (which rarely moves) stays NEUTRAL. Addresses the 0.48% signal
   rate observed across 149 rounds.

---

## 2. Problem

### 2.1 RSI entry extremes

Multiple losing trades entered at unfavourable RSI levels:

| Trade | RSI | Problem |
|-------|-----|---------|
| SOLUSDT LONG | 30.0 | Oversold — caught a falling knife |
| NVDAUSDT SHORT | 26.0 | Oversold — shorted into a bounce |
| NVDAUSDT LONG | 71.0 | Overbought — chased momentum (only survived via invalidation iron rule) |

Each strategy (momentum, breakout, mean-reversion, EMA cross, Bollinger) has its own
internal RSI guard, but no **global filter** blocks a consensus from forming when RSI
is at a statistical extreme. The strategy engine can vote LONG at RSI=75 and SHORT at
RSI=25 — levels where mean reversion is overwhelmingly likely.

### 2.2 MTF over-filtering

`AggregateMTF` (PRD-017) uses TF weights 5m=1.0 / 1h=1.5 / 4h=2.0 with a ±0.1
hysteresis band. In practice the 4h consensus is almost always NEUTRAL (strategies
need ≥2 aligned votes on 48 slow-moving candles), and a single 5m LONG at 0.60
confidence contributes +0.60 to the net — below the 0.1 threshold when the 4h is
neutral. Result: 149 rounds produced only 5 non-WAIT decisions (0.48% signal rate),
while the qualitative Cross-TF line gave 17 directional signals that MTF blocked.

## 3. Goals / Non-Goals

**Goals**
- Block consensus formation when 5m RSI is in the extreme zones (≥75 or ≤25).
- Allow lower-timeframe signals to trigger when the 4h is neutral (not opposing).
- Keep 4h opposition as a hard veto (4h SHORT + 5m LONG → NEUTRAL).

**Non-Goals**
- No change to individual strategy RSI logic.
- No change to TF weights (1.0/1.5/2.0).
- Per-timeframe RSI filtering (only 5m RSI is checked — it's the entry-timing frame).

---

## 4. Requirements

### 4.1 RSI zone entry filter — `internal/strategy/rsi_filter.go` (new)

- **R1.** `RSIFilter(c Consensus, rsi float64) Consensus`:
  - When `c.Direction == Long` and (`rsi >= 75` or `rsi <= 25`): downgrade to
    `Neutral`, confidence=0. Summary appends `"(blocked: RSI %.1f in extreme zone)"`.
  - When `c.Direction == Short` and (`rsi <= 25` or `rsi >= 75`): same downgrade.
  - Otherwise return `c` unchanged.
  - `rsi == 0` (unavailable) → pass through (no block).
- **R2.** Disableable via env: `FRIDAY_RSI_FILTER=false` (default `true`).

### 4.2 Wire RSI into `Consensus` — `internal/strategy/strategy.go`

- **R3.** `Consensus` gains `RSI float64` field (0 = unavailable).
- **R4.** `ConsensusWithRegime` (regime.go) populates `c.RSI` from
  `binance.RSI(closes, 14)` when ≥15 candles available.

### 4.3 Wire filter into `AggregateMTF` — `internal/strategy/aggregator.go`

- **R5.** Before computing the weighted net vote, apply `RSIFilter` to each TF's
  consensus using that TF's own RSI (5m RSI for 5m consensus, etc.).
- **R6.** Export `closesOf` in `internal/binance/indicators.go` as `ClosesOf`
  so the strategy package can call `binance.RSI(binance.ClosesOf(candles), 14)`.

### 4.4 MTF hysteresis and 5m+1h override — `internal/strategy/aggregator.go`

- **R7.** `mtfHysteresis` changes from `0.1` to `0.05`, overridable via
  `FRIDAY_MTF_HYSTERESIS` env (float, default `0.05`).
- **R8.** 5m+1h consensus override (enabled by `FRIDAY_MTF_5M1H_OVERRIDE=true`,
  default `true`): when the 4h is NEUTRAL, 5m and 1h share the same direction,
  and both have confidence ≥0.5, adopt 5m+1h direction with confidence =
  `(5m.Conf + 1h.Conf) / 2`. When the 4h is explicitly opposing (different
  direction), the override does NOT fire — 4h opposition remains a hard veto.

## 5. Acceptance Criteria

- [x] `RSIFilter(Long, 80) → Neutral`; `RSIFilter(Short, 20) → Neutral`
- [x] `RSIFilter(Long, 50) → Long` (unchanged); `RSIFilter(Short, 50) → Short`
- [x] `RSIFilter(Neutral, 80) → Neutral` (no-op)
- [x] `RSIFilter(Long, 0) → Long` (RSI unavailable, pass through)
- [x] `FRIDAY_RSI_FILTER=false` disables the filter
- [x] `AggregateMTF`: 5m LONG 0.6 + 1h NEUTRAL + 4h NEUTRAL → LONG (was NEUTRAL, now >0.05)
- [x] `AggregateMTF`: 5m LONG 0.7 + 1h LONG 0.6 + 4h NEUTRAL → LONG (5m+1h override)
- [x] `AggregateMTF`: 5m LONG 0.7 + 1h LONG 0.6 + 4h SHORT 0.5 → NEUTRAL (4h veto)
- [x] `go build ./...`, `go test ./internal/strategy/...`, `go vet ./...` pass

## 6. Out of Scope / Follow-ups

- Per-timeframe RSI zone calibration (currently only 5m RSI is checked).
- Bollinger %b as an alternative extreme detector (more adaptive than fixed RSI thresholds).
- Adaptive hysteresis that tightens in high-ADX trends and loosens in ranges.
