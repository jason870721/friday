## 1. Summary

Four changes across three layers of the system, all driven by a 106-round live-data
analysis that showed **MTF Strategy NEUTRAL for 97% of rounds** (only 3 actionable
rounds out of 106) and **Analyst output degrading to one-word summaries** after
80+ consecutive NEUTRAL rounds:

1. **5m candle count 20→96** — the structural root cause: EMA cross can't vote, other
   strategies barely qualify. Lifting to 96 candles lets all 5 strategies participate
   on every timeframe.

2. **MTF quorum voting + lower override threshold** — even when strategies fire, the
   MTF aggregation is too conservative: the 5m+1h override needs both TFs at ≥0.5
   confidence. Lower to 0.35 and add a 2-of-3 quorum mode for when the 4h is silent.

3. **Analyst anti-degradation** — after ~80 rounds of "MTF Strategy: NEUTRAL", the
   Analyst (LLM) collapses to one-word "凍結" summaries, losing situational awareness
   and destroying the round log's post-mortem value.

4. **Strategy engine observability** — when MTF Strategy is NEUTRAL there is zero
   visibility into *why*: no strategies fired? fired but conflicted? blocked by RSI
   filter? calibration zeroed out? Surface per-strategy reasons in the MTF output.

## 2. Problem

### 2.1 Structural: 5m candle count (20) starves the strategy engine

`binance_mtf_klines` fetches only 20 5m candles (`internal/tool/binance_mtf_klines.go:60`).
Strategy minimum-candle requirements:

| Strategy | Min candles | Can fire on 5m? |
|----------|------------|-------------------|
| Momentum | 20 | Barely |
| Breakout | 6 | Yes |
| MeanReversion | 20 | Barely |
| EMACross | **50** | **No — "insufficient candles" every round** |
| Bollinger | 21 | Barely (bandwidth unreliable at 20 bars) |

With EMA cross permanently disabled and Bollinger marginal, the 5m timeframe has at
most 3 effective strategies. The `Aggregate` function needs ≥2 aligned directional
votes to form a consensus. Result: the 5m consensus is NEUTRAL in most rounds, which
propagates to MTF Strategy NEUTRAL regardless of 1h/4h.

### 2.2 Aggregation: MTF override too strict, 4h perpetually silent

PRD-022's 5m+1h override requires **both** lower TFs to have confidence ≥0.5.
In practice a single strategy's base confidence is 0.55–0.60, but calibration and
regime weights often reduce it to 0.3–0.5 — below the threshold. The two TFs also
rarely achieve consensus simultaneously: 5m fires first, then 1h catches up later.

The 4h is almost always NEUTRAL (48 slow candles rarely produce ≥2 aligned strategy
votes). With 4h at weight 2.0 contributing zero, the weighted sum defaults to
NEUTRAL unless the override fires — which it doesn't.

Evidence from Session 2 (2026-06-04): BTC rallied +3.2% (62,221→64,223), Cross-TF
showed ALIGNED BULLISH 10+ times, BTC held above 5m MA20 for 10+ consecutive rounds,
yet MTF Strategy stayed NEUTRAL for 87 straight rounds.

### 2.3 Analyst: output collapses after long NEUTRAL streaks

In Session 2, the Analyst output degraded from detailed per-symbol analysis to
one-word summaries:

```
Round 85: "凍結。"
Round 88: "凍結。"
Round 90: "凍結。"
```

The LLM, seeing the same "MTF Strategy: NEUTRAL" output round after round, learns
that no trade will happen and stops producing meaningful analysis. This destroys
the round log's value for post-mortem analysis (PRD-021) and risks missing a real
turn when the market finally breaks out.

### 2.4 Observability: no insight into why MTF Strategy is NEUTRAL

Current MTF output:
```
MTF Strategy: NEUTRAL (5m:NEUTRAL + 1h:NEUTRAL + 4h:NEUTRAL) → weighted NEUTRAL 0.00
```

This tells us nothing. Did 0 strategies fire? Did 2 fire but conflict? Was momentum
LONG blocked by the RSI filter? Did calibration zero out a strategy? Without this
information, tuning the system is guesswork.

## 3. Goals / Non-Goals

**Goals**
- Let all 5 strategies participate on the 5m timeframe (remove the candle-count bottleneck).
- Increase MTF Strategy non-NEUTRAL rate from ~3% to 15–25%.
- Prevent Analyst output degradation on long NEUTRAL streaks.
- Surface per-strategy firing reasons in the MTF Strategy output so NEUTRAL rounds are diagnosable.

**Non-Goals**
- No change to individual strategy logic or thresholds.
- No change to TF weights (1.0/1.5/2.0) — only the aggregation rules around them.
- No new log files or API calls.
- No change to calibration or backtest infrastructure.

## 4. Requirements

### 4.1 Increase 5m candle count — `internal/tool/binance_mtf_klines.go`

- **R1.** Change the 5m entry in `mtfFrames` from `{"5m", 20}` to `{"5m", 96}`.
- **R2.** Update the tool description string: `5m (last 100 min)` → `5m (last 8 hours)`.

Rationale: 96 × 5m = 8 hours, matching the time-span of 1h×24 and 4h×48.
Binance klines endpoint weight is 2 regardless of limit, so no API rate impact.

### 4.2 MTF quorum + lower override threshold — `internal/strategy/aggregator.go`

- **R3.** Lower the 5m+1h override confidence floor from 0.5 to 0.35
  (`lowerTFOverride`, line 218). A value of 0.35 admits calibrated+regime-weighted
  signals that are directionally correct but below the old arbitrary threshold.

- **R4.** Add a quorum mode (env `FRIDAY_MTF_QUORUM`, default `true`):
  When the 4h is NEUTRAL (or absent), use a **2-of-3 quorum** instead of the
  weighted sum:
  - Any 2 timeframes sharing the same direction → adopt that direction,
    confidence = average of the two.
  - All 3 different or all NEUTRAL → NEUTRAL.
  - When 4h IS directional, fall back to the existing weighted-vote path
    (which includes the 4h hard veto).

- **R5.** The quorum check runs *before* the existing 5m+1h override and weighted
  paths. Order: quorum → override → weighted sum.

- **R6.** `mtfHysteresisValue()` and `mtf5m1hOverrideEnabled()` remain unchanged;
  `FRIDAY_MTF_QUORUM` is a new independent knob in `rsi_filter.go`.

### 4.3 Analyst anti-degradation — `internal/orchestrator/prompt_templates.go` + `orchestrator.go`

- **R7.** Add to `analystSystemTmpl` (near the Output section, after the existing
  "請一律使用繁體中文回覆" line):

  > **Analysis quality rule (MANDATORY):** Even when every symbol's bias is NEUTRAL
  > and no trade is expected, you MUST write a concrete, numeric summary for EACH
  > symbol (price, RSI, MA20 relationship, momentum direction) — just as you would
  > for an actionable setup. A one-word summary like "凍結" destroys the round log's
  > post-mortem value. A NEUTRAL round still carries important information: "BTC held
  > 64,200 (RSI 87, overbought), ETH consolidated at 1,797, SOL ranged 71.40-71.50"
  > — write THAT, not "凍結".

- **R8.** Add to `analystSystemTmpl` (near the MTF Strategy paragraph in §3a):

  > When the "MTF Strategy:" line is NEUTRAL for many consecutive rounds but the
  > "Cross-TF:" line repeatedly shows ALIGNED (BULLISH or BEARISH), and price is
  > persistently above/below 5m MA20 — flag this divergence in your analyst_notes.
  > Describe WHAT you are waiting for (e.g. "waiting for MTF Strategy LONG
  > confirmation; BTC needs 1h RSI > 50 or 5m+1h consensus ≥2").

- **R9.** `Orchestrator` tracks `consecutiveNeutral int`. In `runRound`, after the
  deterministic short-circuit (`!anyActionable`), increment it; on an actionable
  round, reset to 0. When `consecutiveNeutral ≥ 10`, inject into the carry for the
  next round:

  > `⚠️ 已連續 N 輪無交易。市場可能在醞釀突破——請保持警惕，不要因長期觀望而降低分析品質。`

  The warning is appended via the existing carry mechanism (like the fee-budget
  warning in PRD-023 R3), and stripped+refreshed each round so it doesn't accumulate.

### 4.4 Strategy engine observability — `internal/strategy/strategy.go` + `aggregator.go` + `binance_mtf_klines.go`

- **R10.** `Consensus` gains a `SignalDetails string` field (empty = no details).

- **R11.** `Aggregate` populates `SignalDetails` from the input signals, one line
  per strategy:
  - Directional: `"momentum LONG(0.55) inval=63250"`
  - Neutral with reason: `"mean_reversion: not stretched (1.2% from MA20, RSI 45)"`
  - Insufficient data: `"ema_cross: insufficient candles (have 20, need 50)"`
  - For NEUTRAL consensus, append the reason: `" — only 1 directional (need ≥2)"`
    or `" — conflict (momentum LONG vs breakout SHORT)"`.

- **R12.** `RSIFilter` appends to `SignalDetails` when it blocks a signal:
  `" (blocked: RSI 78.3 in extreme zone)"`.

- **R13.** `mtfPart` appends each TF's `SignalDetails` (when non-empty) as an
  indented line beneath the MTF Strategy summary line, producing output like:

  ```
  MTF Strategy: NEUTRAL (5m:NEUTRAL + 1h:NEUTRAL + 4h:NEUTRAL) → weighted NEUTRAL 0.00
    5m: momentum LONG(0.55) inval=63250 — only 1 directional (need ≥2)
    1h: mean_reversion LONG(0.18) — regime-weighted down from 0.60 in TRENDING
    4h: none fired (bollinger inside bands, ema_cross insufficient candles)
  ```

- **R14.** The `binance_mtf_klines` tool output already prints `MTF Strategy: …`
  via `fmt.Fprintf(&b, …)`; the details are already part of the summary string
  produced by `AggregateMTF`, so the tool requires no format change.
